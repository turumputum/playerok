# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

PlayerOK is a kiosk-style media playback appliance running on Debian. It plays a fullscreen video loop on the connected display and broadcasts per-language audio tracks over IP multicast (RTP) to network audio receivers ("controllers") in response to MQTT triggers (e.g. physical button panels).

The codebase is **not one application** — it is several independent Node.js services + one Python service that coordinate exclusively through MQTT (mosquitto on `127.0.0.1:1883`, plus a WebSocket listener on `:1890` used by the in-browser MQTT console). Each module is its own npm project with its own `node_modules`. There is no monorepo tooling; install is per-module.

## Modules / services

| Path | Type | systemd unit | Purpose |
|---|---|---|---|
| [supervisor/supervisor.js](supervisor/supervisor.js) | Node, root | `supervisor.service` | Watches `meta/player_config.json`, fires per-section sub-scripts (`set_time_config.js`, `set_net_config.js`, `set_security_config.js`, `set_log_config.js`) when relevant section changes. Forks `usb_storage.js` and `uart2mqtt.js` as children with auto-restart. **Wipes all logs in `/home/playerok/playerok/logs/` on every start.** |
| [scheduler/scheduler.js](scheduler/scheduler.js) | Node | `scheduler.service` | Reads `meta/scheduler-table.json`, schedules tasks. Spawns `player/player.js` as child for `multimedia` tasks. Owns process tree: scheduler → player.js → mpv (and player.js → audio_worker.py). Has a 30-second health check (`[health] OK \| ...`) for player.js and mpv. Reaps orphan mpv/player.js/audio_worker.py before each spawn (`reap_orphan_mpv`). |
| [player/player.js](player/player.js) | Node | (spawned by scheduler) | One per scheduled task. Drives mpv via [node-mpv](https://www.npmjs.com/package/node-mpv) over `/tmp/node-mpv.sock`, subscribes to MQTT triggers per playlist, runs its own 30-second health check (`vo-configured`, `idle-active`, `time-pos`); on unhealthy, calls `process.exit(1)` and lets the scheduler watchdog respawn. |
| [player/audio_worker.py](player/audio_worker.py) | Python (GStreamer) | (spawned by player.js) | Long-lived helper holding **pre-warmed** GStreamer pipelines (one per `network_audio.streams[*]` entry in the playlist) in `PAUSED` state. On a `play` JSON command on stdin, transitions to `PLAYING` (~5–10 ms latency). Replaces the old per-trigger `gst-launch-1.0` spawns which had ~230–470 ms cold start. Talks to player.js over **stdin/stdout JSON**, one message per line. |
| [webKa/index.js](webKa/index.js) | Express, port **80**, root | `webka.service` | The web UI. Pug templates in [webKa/views/](webKa/views/), assets in [webKa/assets/](webKa/assets/). Renders the file manager, playlist editor, scheduler editor, and live MQTT console. **Reads `mosquitto` directly via the WebSocket listener (`ws://${host}:1890/mqtt`)**, not via the Node MQTT client — see [home.pug](webKa/views/home.pug) MQTT console block. |
| [wbk/](wbk/) | Express + React + MongoDB | (separate, optional) | Newer file manager (Docker-based, MongoDB-backed). Independent from webKa's built-in file manager at [webKa/views/list.pug](webKa/views/list.pug). |
| [uart2mqtt/uart2mqtt.js](uart2mqtt/uart2mqtt.js) | Node | (forked by supervisor) | Bridges serial-attached devices ↔ MQTT topics. |
| [supervisor/daemon_screen_sound_config.js](supervisor/daemon_screen_sound_config.js) | Node, root | `screen_sound_config.service` | Applies screen/sound config from `meta/player_config.json`. |

mpv runs on **tty3** with `--vo=gpu --hwdec=vaapi --fullscreen --really-quiet`. Xorg/lightdm runs on vt7 (showing a custom "black screen" X-session at [/usr/local/bin/black-screen-session.sh](file:///usr/local/bin/black-screen-session.sh) configured via `/etc/lightdm/lightdm.conf.d/50-autologin.conf`). The mpv on tty3 takes the display via DRM/KMS independent of Xorg.

## State files

All services share state through JSON files in [meta/](meta/) and [data/](data/). There is no database (except wbk's separate MongoDB).

| File | Owner / writer | Watched by |
|---|---|---|
| `meta/player_config.json` | webKa (`/save_config`), player.js (writes `sound.volume` on every volume change!) | supervisor → triggers `set_*_config.js` per changed section |
| `meta/scheduler-table.json` | webKa | scheduler — `touch` it to trigger `scheduler_init` (kills+respawns player) |
| `meta/playlist-table.json` | webKa | (read-only, list of playlists) |
| `meta/content-table.json` | regenerated by [supervisor/content_table_update.js](supervisor/content_table_update.js) when files in `data/` change | (consumed by editor frontend) |
| `data/playlists/*.json` | webKa | scheduler `playlist_watcher` triggers `scheduler_init` |
| `data/content/*` | wbk + webka uploaders | content_table_update |

Note: `meta/player_config.json` is **not** tracked in git — its on-device modifications (volume, network) are local state. Same for the playlist files in `data/playlists/`.

## MQTT topic conventions

- `scheduler/restart` payload `1` — re-run `scheduler_init`
- `scheduler/current_player_task` (retained) — current playlist path
- `scheduler/runing_scripts_list` (retained) — list of active script tasks
- `player/{volume_val,next,prev,play_pause,stop}` — control current player
- per-playlist track triggers: arbitrary topics defined in playlist (e.g. `mbGlassPanBt/button_2`)

## Common operations

### Install (one-time, per module)
```sh
cd webKa && npm i && bower install bootstrap-treeview
cd scheduler && npm i
cd player && npm i
cd supervisor && npm i
cd uart2mqtt && npm i
cd meta/tools && npm i
sudo apt install python3-gst-1.0 gstreamer1.0-plugins-{base,good,bad,ugly} gstreamer1.0-libav
```

### Apply code changes without sudo
**Restart player only** (without bouncing scheduler systemd unit) — touch the table:
```sh
touch /home/playerok/playerok/meta/scheduler-table.json
```
This trips `scheduler/table_watcher` → `stopAllTask()` → `scheduler_init()` → respawn player.js with the new code. Also picks up a new `audio_worker.py`. Use this for player.js / audio_worker.py / scheduler-internal-logic edits as long as the scheduler process itself didn't change.

### Apply scheduler code changes (needs sudo)
```sh
sudo systemctl restart scheduler.service
```
`KillMode=control-group` (default) — wipes all children (player.js, mpv, audio_worker.py) cleanly. `ExecStartPre=/bin/sleep 10` adds 10 s delay before scheduler starts; budget 14+ s before checking new state.

### Apply webKa code changes
Pug templates auto-reload on next request (Express dev mode, no view cache). Server-side JS edits need:
```sh
sudo systemctl restart webka.service
```

### Syntax check
```sh
node -c path/to/file.js
python3 -c "import ast; ast.parse(open('player/audio_worker.py').read())"
```

### Trigger an MQTT message from the device (no `mosquitto_pub` installed)
```sh
node -e "
const mqtt = require('/home/playerok/playerok/player/node_modules/mqtt');
const c = mqtt.connect('mqtt://127.0.0.1:1883');
c.on('connect', () => c.publish('TOPIC', 'PAYLOAD', { qos: 1 }, () => { c.end(); process.exit(0); }));
"
```

### Probing mpv state
```sh
python3 -c "
import socket, json
s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM); s.settimeout(2); s.connect('/tmp/node-mpv.sock')
for p in ['filename','time-pos','vo-configured','idle-active','playlist-count','loop-file']:
    s.send(('{\"command\":[\"get_property\",\"'+p+'\"]}\n').encode())
    print(p, s.recv(2048).decode().strip())
"
```

### Logs to read
[/home/playerok/playerok/logs/](logs/): `scheduler.log`, `player_log.log`, `webKa.log`, `supervisor.log`, `screen_sound_config.log`, `usb_storage.log`, `uart2mqtt.log`. **All wiped at supervisor start.** For history before the last reboot, use `journalctl -b -N <service>`.

## Conventions / pitfalls discovered while debugging

- **`req.body` parsing in webKa.** Send `Content-Type: application/json` from the frontend. Older code used `application/x-www-form-urlencoded` + `JSON.stringify(...)` body; this caused bodyParser.urlencoded to URL-decode `%20`/`+` inside the JSON before it was parsed, breaking any rename/move/save of files with `%`/`+`/`&` in names. Server-side: use `req.body` directly, **not** `JSON.parse(Object.keys(req.body)[0])`.
- **`req.url` is percent-encoded; `req.params[0]` is decoded.** Use `req.params[0]` for filename routes (e.g. `/data/*@upload`, `/data/*@rename`). The `@upload` handler at [webKa/index.js:265](webKa/index.js#L265) used to use `req.url.replace("@upload", '')` — that's how files ended up on disk with literal `%20` in their names.
- **scheduler interval semantics.** A schedule like `start_time: 00:00 / end_time: 23:59` is interpreted by [scheduler.js](scheduler/scheduler.js) as "stop at 23:59, restart at 00:00". To avoid the daily 1-minute black-screen + mpv-respawn (which used to fail because of orphan mpv DRM contention), `stop_task` short-circuits when the next `start_time` is within 90 s — see `CONTINUOUS_GAP_THRESHOLD_MS`. **Manual stops pass `force=true`** (the default) to bypass the short-circuit; only the timer-driven `stop_task(index, false)` opts in.
- **Process leaks.** mpv on tty3 doesn't auto-die when its parent (player.js) dies — DRM master can stick on the orphaned mpv and block the next mpv from grabbing the screen. Always go through `start_player` → `reap_orphan_mpv` (in scheduler.js) which `pkill -9`s any stale `mpv.*node-mpv.sock`, `player/player.js`, and `player/audio_worker.py` before spawning fresh. **Don't add new long-lived child processes without adding them to `reap_orphan_mpv`.**
- **mpv is `--really-quiet`** (forced by node-mpv when `verbose: false`). When mpv goes silent and `vo-configured: false`, you cannot see why from logs. Check the playlist file paths — file-not-found is invisible. The health check catches this case (it kills the player so the scheduler respawns).
- **Volume write feedback loop.** [player/player.js](player/player.js) `set_volume()` writes to `meta/player_config.json` whenever a `volume_val` MQTT arrives. supervisor sees the change and runs `set_config()`. This is benign as long as nothing in `time/security/net/log` sections changed (those would respawn services).

## Adding a new track type / pipeline element

Audio streaming goes through [player/audio_worker.py](player/audio_worker.py). Each entry in `playlist.tracks[i].network_audio.streams[]` becomes a single `Gst.Pipeline` keyed `t<trackIdx>_s<streamIdx>`. Pipeline is built by `parse_launch` in `AudioStream.__init__` from `filesrc → decodebin → audioconvert → audioresample → volume → audioconvert → (rtpL16pay|opusenc+rtpopuspay) → udpsink`. Multicast destinations must be unique within a playlist — webKa enforces this in `validatePlaylistMulticastCollisions` (`/save_playlist` rejects with HTTP 400 + `multicast_collision` JSON if two enabled streams share `host:port`).
